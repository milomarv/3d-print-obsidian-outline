# 3d-print-outline

Auto-generates Obsidian `_index.md` files for a 3D-printing project vault. Walks the vault, writes one `_index.md` per folder, lists CAD/STL/3MF assets per project, embeds image galleries, links sub-projects, and pulls filament metadata from Spoolman. Idempotent, fence-protected, safe to re-run from cron / n8n / a skill.

## Prerequisites

- Python 3.13+
- `uv` (installed via `curl -LsSf https://astral.sh/uv/install.sh | sh`)

## Install

```bash
git clone git@github.com:milomarv/3d-print-outline.git ~/Projects/3d-print-outline
cd ~/Projects/3d-print-outline
./install.sh
```

The `install.sh` script runs `uv tool install --force --editable . --with pyyaml`, installing the `outline` console script to `~/.local/bin/`. Verify the installation:

```bash
outline --help
```

## Usage

Regenerate all `_index.md` files in your vault:

```bash
outline /home/milomarv/3d-print-vault
```

### Flags

- `--dry-run` — print unified diffs per file; do not write changes.
- `--no-spoolman` — skip Spoolman API lookups even if reachable.
- `--config PATH` — use a custom config file instead of auto-detected locations.
- `-v`, `--verbose` — enable debug-level logging.

## Vault Layout

The expected structure is:

```
<vault>/
├── _index.md              (auto-generated)
└── projects/
    └── <project-slug>/
        ├── _index.md      (auto-generated; richer than top-level)
        ├── notes.md       (user-edited; carries filaments metadata)
        ├── cad/           (parametric / native CAD source)
        ├── stl/           (mesh exports)
        ├── 3mf/           (sliced output: .3mf, .gcode, .bgcode)
        └── images/        (previews; embedded in _index.md)
```

A folder under `projects/` is recognized as a **project** if it directly contains any of: `cad/`, `stl/`, `3mf/`, or `images/`.

Projects can nest: `projects/<parent>/<child>/` with the same marker subdirs creates a sub-project. Both parent and child get an `_index.md`. The parent's index lists children under "Sub-projects" and excludes their files from parent tables.

## Fence-Marker Contract

The tool writes generated content between HTML comment markers and never modifies anything outside:

```markdown
<!-- AUTO-GENERATED by 3d-print-outline; do not edit between AUTO fences -->

<!-- BEGIN AUTO -->
... regenerated content ...
<!-- END AUTO -->

Your hand-written prose, curated tables, photo commentary, etc. are preserved.
```

**Idempotency**: If regenerated content matches the existing content byte-for-byte, the file is not rewritten. This protects file modification times from being unnecessarily updated (important for tools like Syncthing).

**Protected files**: The tool never modifies `notes.md`, asset folders (`cad/`, `stl/`, `3mf/`, `images/`), `.obsidian/`, or `.stignore`.

## Filament Linking (Spoolman Integration)

Projects can reference spools from [Spoolman](https://github.com/donkie/spoolman) via YAML frontmatter in `notes.md`:

```markdown
---
filaments: [12, 34]
---
# Project notes...
```

The tool fetches spool metadata from the Spoolman API, caches results in-process, and deduplicates across a single run. A Filaments table is rendered in the project's `_index.md` with material, color, weight, and other spool details.

If the Spoolman API is unreachable or disabled via `--no-spoolman`, the tool falls back to displaying the raw spool IDs.

## Configuration

Config resolution order (first match wins):

1. `--config PATH` (command-line override)
2. `<vault>/.outline.toml` (vault-local config)
3. `~/.config/3d-print-outline/config.toml` (user global config)
4. Built-in defaults

See `outline.toml.example` in the repo for all available options, including:
- File extensions for CAD, STL, 3MF, and image files
- Vault layout (project root folder, subdirectory names)
- Exclusions (directories and glob patterns to skip)
- Render settings (fence markers, header comment)
- Spoolman API endpoint and timeout

## Automation with n8n

The tool is designed to run periodically or on-demand via workflows. Example n8n integration:

The `homenet-outline-runner` workflow runs `outline` and `graphify-outline` in parallel branches (triggered manually or on schedule) over SSH:

```bash
~/.local/bin/outline /home/milomarv/3d-print-vault
```

This approach ensures your vault stays up-to-date without manual intervention.
